# Production-readiness audit — 2026-09-06

Scope: all of `backend/app` (~20.6k lines, 131 files), `tools` (8 files),
`frontend/src` (52 files), `tests` (74 files, 1037 tests), `deploy`,
`.github/workflows`, and `docs`.

Method: twelve parallel subagents — seven research topics against primary
sources, five audit fan-outs over the tree. Every finding below carries a
`file:line`. Findings marked **[verified]** were re-checked by hand in the
main session; the rest are as reported by the agent that found them, and
the per-area files under `docs/notes/2026-09-audit-*.md` and
`docs/notes/2026-09-research-*.md` carry the full evidence.

---

## 1. The organising theme: absence of evidence rendered as a positive claim

This repo is unusually careful about one specific thing, and that care is
its best design decision. `ProviderServer` distinguishes `None` ("this
collector could not read it") from `0`/`()` ("read, and there are none").
`IngestService` carries a stored value forward for a `None`.
`Server.unread_fields` records what a run could not read and is
recomputed rather than merged. A Redfish PSU reporting `Absent` is
dropped, never counted as failed. A GPU model that shipped in two
capacities has no bare-name catalog row, so it stays `None` rather than
guessing. Every one of those is the same rule: **do not turn "we did not
look" into "there is nothing there."**

The single highest-value result of this audit is that **the rule is
violated in four places, none of which were on the brief's known-problems
list**, and in each one the violation is invisible because the system
reports success:

| # | Where | What it claims | What is true |
|---|---|---|---|
| A | `oneview/provider.py` | exit 0, run complete | The run may have missed the fleet; OneView cannot report a collection error at all |
| B | `frontend/.../SitesOverviewPage.tsx:236` | "● all healthy" | Every server in the site may be `UNKNOWN` — never evaluated |
| C | `frontend/.../NetworkTab.tsx:108` | "No network interfaces." | The NICs may simply not have been read this run |
| D | `tools/run_collector.py` `_UNFILTERED_TYPES` | exit 0, run complete | Untested; flipping it ingests zero standalone BMCs and still exits 0 |

They are separate bugs in separate languages found by four different
agents, and they are the same bug. Ranking them together, and fixing them
in phases that state that rule explicitly, is worth more than fixing them
as four unrelated tickets.

## 2. What is already good

Stated first and in specifics, because a finding list that pretends
otherwise is noise.

- **The carry-forward `None` semantics and `unread_fields`** (§1). The
  backend gets this right end to end, including the subtle part —
  `unread_fields` is recomputed from scratch every ingest and never
  merged, so a path that is no longer `None` stops being flagged.
- **`HardwareTab.tsx`** implements the not-read / carried-forward / read
  distinction *exactly* right. It is the model the other tabs should copy.
- **Keyset pagination with an HMAC-signed cursor**, and every non-search
  query shape measured at `keys == docs == nReturned == 51` on its
  declared index at both 10k and 50k. `verify_indexes` clean at 50k.
- **Test suite discipline**: zero `unittest.mock` across 1037 tests —
  hand-written fakes throughout — and zero unannotated test functions
  across 1,059. Both collector drift guards correctly derive their
  expected set from `tools.run_collector.PROVIDER_FACTORIES` rather than
  restating it.
- **`redfish`'s deliberate no-retry-on-5xx** to avoid BMC account
  lockout, and its cancellation-shielded session `DELETE`. Both are
  correct and neither is obvious.
- **The layered architecture actually holds.** 4 of 5 import-linter
  contracts pass today, including `app.domain` never reading `Settings`
  and never reaching into infrastructure.
- **`structlog` config** (`infrastructure/logging/config.py`) is sound,
  and there is no `%`-format or f-string interpolation in any log call in
  the repo.
- **The ADR discipline.** 22 ADRs, all nine CI action SHAs verify to
  their claimed tags, `.env.example` has zero drift against the 70
  settings fields the code reads, and `requirements.txt`/`pylock.toml`
  are in sync with `pyproject.toml`.
- **`ProviderServer` as `frozen=True, slots=True`** is measurably right,
  not merely tasteful: 50k instances cost 259 ms / 5.2 MB as a dataclass
  versus 491 ms / 56.8 MB as a Pydantic model — ~11x the heap.

### 3.5 Performance — all measured, none speculative

Baseline at 10k and 50k servers, one uvicorn worker (full numbers and
method in `2026-09-research-performance.md`; raw output in the scratchpad):

- Concurrency sweep, default list page @50k: c=1 → 3.7 ms p50 / 248 req/s;
  c=4 → 11.1 ms / 352; c=16 → 45.0 ms / 348; c=32 → 102.9 ms / 298.
  **Throughput saturates at ~350 req/s from c=4 and then degrades.**
- Server-side @50k: `/health/live` 0.34 ms; list `page_size=1` 2.14 ms;
  50 rows 3.33 ms; 200 rows 6.58 ms; cache miss 12.14 ms;
  `with_count=true` miss **32.25 ms**.
- Latency is essentially **independent of collection size** (10k vs 50k
  within noise).

### 3.6 The provider contract (Phase 1 input)

Current `ServerInventoryProvider` is a 3-member `Protocol`
(`provider_type`, `health_check`, `list_servers`) for seven
implementations whose real lifecycle has six steps.

Per-provider shape, measured:

| Provider | Auth | Releases session | List/detail split | `collection_errors` | Run budget | Streams |
|---|---|---|---|---|---|---|
| `fake` | none | n/a | single-pass | **no** | no | yes |
| `ucs_manager` | one login/domain | yes | single-pass | **no** | no | yes |
| `ucs_central` | Central + UCSM login per discovered domain | yes | yes | yes | no | yes |
| `intersight` | none — `hs2019` signing | yes | yes | yes | yes | yes |
| `openmanage` | **two** (OME + shared iDRAC) | yes | yes | yes | no | yes |
| `oneview` | one (`Auth:` header) | yes | yes | **no** | no | **no** |
| `redfish` | one session per BMC | yes (shielded) | yes | yes | yes | yes |

- **`collection_errors` is missing from three providers, not two.** The
  brief says `fake` and `ucs_manager`; it is also missing from
  `oneview` — finding C1.
- **No provider implements `__aenter__`/`__aexit__` or any logout hook**,
  so the brief's "a leaked vendor session becomes impossible" is a real
  gap across all seven. `tools/verify_oneview.py` logs out by hand
  because an open OneView session is a genuine resource.
- **`collection_errors_of` (`run_collector.py:517`) is `object`-typed and
  reflective**, so it maps "run complete" and "provider cannot report
  this" to the same `()` → exit 0. It has already been copy-pasted into
  `openmanage/provider.py:205`. Its own docstring argues *against*
  promotion, calling it "ceremony for a single vendor's shape" — that
  reasoning is falsified now that a second vendor needs it.
- **~520 lines of duplication** the contract should absorb: six
  near-identical `_new_client()`; five "open a client, close it"
  `health_check`s; five logout-swallow-and-warn blocks; four
  `collection_errors` property+field pairs; four hand-rolled pagination
  loops; three ~30-line endpoint validators; four name-regex sites.
